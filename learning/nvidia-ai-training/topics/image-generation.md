# 🎨 Image Generation — 이미지 만들기·바꾸기

> **참고 강의:** `[LLM] 02. Multimodal.pdf`, p.13~26  
> **상태:** 강의 내용 요약 · 실습 완료 여부 미확인

## 1. 어떤 API를 사용하나요? (p.14~15)

| 작업 | 강의의 분류 | 결과 |
|---|---|---|
| 사진을 보고 설명하기 | Responses API의 Vision 입력 | 텍스트 |
| 글만으로 그림 만들기 | Images API `generate` | 이미지 |
| 원본 그림을 바꾸기 | Images API `edit` | 편집된 이미지 |

**중요:** 이미지 **이해**와 이미지 **생성**을 구분하여 도구를 선택합니다. Responses API에서도 도구를 통한 이미지 생성 방식이 있을 수 있다고 강의에서 언급합니다. (p.15)

## 2. Text-to-Image 원리 (p.16~17)

강의에서는 **텍스트의 의미를 반영하면서 노이즈를 점차 제거해 그림을 만드는 과정**을 비유적으로 보여줍니다.

- 요청: 어떤 그림을 원하는지 텍스트로 설명
- 생성 과정: 초기 노이즈에서 이미지 특징을 점진적으로 형성
- 결과: 프롬프트와 관련된 이미지 출력

위 내용은 슬라이드의 학습용 요약이며 실제 모델별 아키텍처는 다를 수 있습니다.

## 3. Base64가 왜 필요한가요? (p.19, 24)

강의의 예제에서는 이미지 결과가 Base64 문자열로 반환됩니다.

1. 생성 API로 이미지 요청
2. 응답에서 Base64 데이터 추출
3. Base64 문자열을 **이진 파일 데이터로 변환**
4. `.png` 등 이미지 파일로 저장
5. Colab 또는 Gradio에서 이미지 표시

**핵심 구분:** Base64 문자열 자체는 PNG 파일이 아닙니다. 디코딩한 데이터를 파일로 저장해야 이미지로 표시할 수 있습니다.

## 4. Gradio 이미지 컴포넌트 (p.21~23)

| 컴포넌트 | 용도 | 알아둘 요소 |
|---|---|---|
| `gr.Image` | 한 장의 이미지 입력·출력 | `type`: numpy / pil / filepath |
| `gr.Gallery` | 여러 이미지 목록 표시 | `columns`, `rows` |
| `gr.ImageEditor` | 이미지에 그리기·수정 | `background`, `layers`, `composite` |

### ImageEditor의 세 항목

- **background:** 원본 이미지
- **layers:** 사용자가 덧그린 레이어
- **composite:** 합쳐진 결과

## 6. 모델·비용 메모 (p.18)

강의에서는 비용을 고려하여 **`gpt-image-1-mini` 사용을 지정**합니다. 이는 교육 과제의 권장 모델이며, 오늘의 가격표나 사용 가능 여부를 실시간 검증한 것은 아닙니다.
