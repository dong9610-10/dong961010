## 2. Tool Calling

### 2.1 외부 도구의 필요성 (4–8쪽)

LLM의 사전학습 지식만으로는 현재 날씨처럼 변하는 정보를 확정할 수 없다. 외부 도구를 연결하면 웹 검색, API 요청, 데이터 조회 등의 실행 결과를 답변에 활용할 수 있다.

| 구분 | Custom Function | Built-in Tool |
|---|---|---|
| 기능 정의 | 개발자가 함수 및 스키마 작성 | OpenAI가 제공하는 도구 유형 지정 |
| 실행 | 애플리케이션 측에서 함수 호출 | 도구 유형에 따라 제공 측에서 처리 |
| 예시 | 날씨 조회 함수 | 웹 검색, 파일 검색 |

### 2.2 Function Calling 처리 흐름 (9–15쪽)

강의는 모델의 함수 호출 요청을 제안서에 비유한다. 모델이 함수 이름과 인자를 반환해도 사용자 정의 함수가 자동으로 실행되는 것은 아니다.

1. 사용자 질문과 `tools` 목록을 Responses API에 전달한다.
2. 모델이 필요한 도구와 인자를 선택해 `function_call`을 반환한다.
3. 애플리케이션에서 `response.output`을 순회하며 호출 항목을 찾는다.
4. `json.loads(item.arguments)`로 JSON 문자열을 Python 객체로 변환하고 해당 함수를 실행한다.
5. 실행 결과를 `function_call_output`으로 구성하고 원래 호출의 `call_id`를 포함한다.
6. 이전 응답과 도구 결과를 모델에 다시 전달하여 최종 답변을 생성한다.

```text
사용자 질문 → 모델의 함수 호출 요청 → 개발자 코드에서 실행
           → 실행 결과 전달 → 모델의 최종 답변
```

### 2.3 JSON Schema

도구 이름, 기능 설명, 입력 타입, 필수 입력을 정의한다. 함수의 내부 코드 대신 이러한 설명을 바탕으로 모델이 호출 여부를 판단한다.

날씨 조회 예시의 핵심 구성:

| 필드 | 의미 |
|---|---|
| `type` | 도구 유형: function |
| `name` | 함수 식별자: get_weather |
| `description` | 도구의 용도와 사용 조건 |
| `parameters.type` | 인자 객체의 타입: object |
| `properties.city` | 도시 이름을 받는 string 입력 |
| `required` | 필수 입력: city |

강의 초반의 날씨 함수는 모의 데이터 예제이며 실시간 기상 조회와 구분해야 한다.

### 2.4 Built-in Tools (17–20쪽)

강의에서는 웹 검색, 파일 검색, 코드 실행, 이미지 생성, 컴퓨터 사용, Remote MCP 등을 소개한다. 웹 검색 예제에서는 `tools=[{"type": "web_search"}]` 형태로 도구를 제공한다.

사용 가능한 도구와 모델 조합, 비용은 실제 사용 환경에서 확인할 필요가 있다.

## 3. Requests와 외부 API (22–32쪽)

### 3.1 HTTP 요청 및 응답

요청은 URL, Method, Headers, Body 등으로 구성된다. 응답에는 상태 코드, 헤더, 실제 데이터가 포함된다.

| Method | 일반적인 용도 |
|---|---|
| GET | 데이터 조회 |
| POST | 데이터 생성 또는 처리 요청 |
| PUT / PATCH | 데이터 수정 |
| DELETE | 데이터 삭제 |

| 상태 코드 | 의미 |
|---|---|
| 200 / 201 | 성공 / 생성 성공 |
| 400 | 잘못된 요청 |
| 401 / 403 | 인증 또는 접근 권한 문제 |
| 404 | 요청 대상 없음 |
| 500 | 서버 내부 오류 |

Python의 `requests.get()`으로 요청하고 `response.status_code`, `response.headers`, `response.json()` 등으로 결과를 확인한다. HTTP 성공 코드가 JSON 파싱 성공을 보장하지는 않으므로 응답 형식도 확인해야 한다.

### 3.2 Open-Meteo 날씨 API

- Geocoding API: 도시 이름으로 위도와 경도 조회
- Forecast API: 위도·경도를 입력해 현재 기온 등의 기상 정보 조회
- 강의 예제는 `latitude`, `longitude`, `current` 파라미터를 전달한다.
- `current`의 `temperature_2m` 등 필요한 필드를 추출한다.

31쪽 실습에서는 도시명을 영문으로 처리하고 기온·습도를 조회하는 챗봇을 요구한다.

```text
도시 이름 → Geocoding API → 위도·경도
         → Forecast API → 기온·습도 → LLM 답변 → Gradio
```

API 호출 한도 및 실제 응답 구조는 실행 시 확인한다.

## 4. MCP (34–67쪽)

### 4.1 개념과 역할

Model Context Protocol은 AI 애플리케이션과 외부 도구를 연결하기 위한 표준 규격이다.

| 구성 | 역할 |
|---|---|
| Host | 사용자가 사용하는 AI 애플리케이션 |
| Client | Host 내에서 MCP 서버와 통신하는 연결 구성 요소 |
| Server | 도구와 외부 데이터 접근 기능 제공 |

Tool Calling은 모델이 도구 사용을 요청하고 결과를 활용하는 과정이며, MCP는 다양한 애플리케이션에서 도구를 표준화된 방식으로 연결하도록 돕는다.

### 4.2 로컬 개발 환경

강의자료는 VS Code와 Python 3.14.x 환경을 제시한다. 실제 강사 화면에서는 Python 3.11 (64-bit)을 사용한 것으로 확인된다.

실습에 필요한 라이브러리: `openai`, `python-dotenv`, `fastmcp`; 외부 API 실습에는 `requests` 사용.

API 키는 `.env`의 환경 변수로 관리하고 `.gitignore`로 공개 저장소에서 제외한다.

### 4.3 FastMCP 서버 (46–56쪽)

- `FastMCP()`: 서버 객체 생성
- `@mcp.tool`: Python 함수를 MCP 도구로 등록
- 타입 힌트와 함수 설명: 도구 입력 스키마 및 설명 구성에 활용
- `mcp.run()`: 서버 실행

좋은 도구는 함수 및 인자 이름이 구체적이고, 설명에서 기능과 사용 조건이 명확하다.

| CLI 명령 | 목적 |
|---|---|
| `fastmcp list server.py` | 도구 목록 확인 |
| `fastmcp call server.py get_weather` | 특정 도구 직접 테스트 |
| `fastmcp run server.py` | 서버 실행 |

### 4.4 FastMCP 클라이언트 (57–67쪽)

`Client("server.py")`로 클라이언트를 구성하고 `async with`로 연결한다. `await client.call_tool()`로 이름과 인자를 전달하며, `asyncio.run()`으로 비동기 진입 함수를 실행하는 흐름을 학습한다.

`list_tools()`로 가져온 MCP 도구의 이름, 설명, 입력 스키마를 OpenAI Responses API의 function tool 형식으로 변환할 수 있다.

| MCP 도구 정보 | Responses API 필드 |
|---|---|
| name | name |
| description | description |
| input schema | parameters |

모델의 도구 호출을 MCP 클라이언트에서 실행한 뒤 결과를 `function_call_output`으로 반환한다. `previous_response_id`를 이용해 이전 모델 응답과 연결하는 방법도 다뤘다. 여러 번의 도구 호출이 필요한 구현에서는 각 응답과 결과를 반복적으로 처리해야 한다.

## 5. Remote MCP와 Connector (69–79쪽)

| 구분 | 연결 방식 |
|---|---|
| Local MCP | 로컬 서버를 클라이언트에서 호출 |
| Remote MCP | 접근 가능한 원격 MCP 서버 URL을 Responses API에 전달 |
| Connector | OpenAI에서 관리하는 서비스별 연결 도구 식별자 사용 |

Google Calendar 예제에서는 OAuth 액세스 토큰을 환경 변수로 관리하고 `connector_id`, `authorization` 등을 이용한다. 오늘 일정을 조회하려면 날짜와 시간대도 명확하게 지정할 필요가 있다.

Remote MCP 예제에서는 `type: mcp`, `server_label`, `server_url`을 설정하고, 응답의 `mcp_call` 항목과 최종 텍스트를 확인한다.

강의 예시에는 승인 생략 옵션이 포함되지만 실제 개인정보 접근이나 외부 변경 작업에서는 최소 권한 및 승인 정책을 별도로 검토해야 한다.

## 7. VS Code 실습 및 오류 확인

### 7.1 기본 API 호출

사용자가 공유한 코드에는 `load_dotenv()`, `os.getenv("OPENAI_API_KEY")`, `OpenAI(api_key=api_key)` 및 `client.responses.create()`를 사용하는 구조가 포함됐다.

강사 실행 화면에서는 도구 없이 현재 서울 날씨를 질문하자 실시간 정보를 제공할 수 없다는 답변이 출력됐다. 사용자 코드도 유사한 구조였으나 본인의 실행 성공 여부는 확인되지 않았다.

`response.output`은 전체 출력 항목을 확인하는 데 사용하며, `response.output_text`는 텍스트 답변을 편리하게 확인할 때 사용한다.

### 7.2 개발 환경 경고

| 확인된 경고 | 의미 및 대응 |
|---|---|
| Pylance: openai 가져오기 실패 | 선택한 인터프리터에서 패키지를 찾을 수 없음. 설치 및 인터프리터 확인 |
| Pylance: dotenv 가져오기 실패 | python-dotenv 설치 및 환경 확인 |
| Ruff I001 | import 블록 정렬·서식 경고. 일반적인 실행 오류와 구분 |

안내한 설치 명령은 `python -m pip install openai python-dotenv`이다. VS Code의 Python 인터프리터 선택 기능으로 실제 설치 환경과 일치시키는 방법도 확인했다. 경고가 사라졌는지에 대한 후속 화면은 없었다.

### 7.3 개발 도구 활용

VS Code의 Codex를 코드 설명, 문법 질문, 오류 원인 확인에 사용하는 방법을 논의했다. 교육 중에는 강사 코드의 구조를 유지하고 요청하지 않은 자동 수정을 피하는 방식으로 활용한다.
