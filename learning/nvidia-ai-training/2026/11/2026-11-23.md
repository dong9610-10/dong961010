## 2. 핵심 개념

### 2.1 Multimodal과 Vision (4–12쪽)

- Unimodal: 한 종류의 데이터 형태를 중심으로 처리
- Multimodal: 텍스트·이미지·음성 등 여러 형태를 함께 처리
- Vision: 입력 이미지를 분석하고 질문에 대한 텍스트 답변 생성
- Image-to-Text: 이미지의 시각 정보를 텍스트로 연결

강의는 Vision Encoder와 Text Decoder를 중심으로 이미지 설명이 생성되는 흐름을 설명합니다. 이 구성은 개념을 이해하기 위한 예시이며 모든 모델의 내부 구조가 동일하다는 의미는 아닙니다.

Responses API에서는 메시지의 `role`과 `content`를 사용하고, `content`에 `input_text` 및 `input_image` 등을 함께 전달할 수 있습니다.

이미지 속 작은 글자, 흐린 텍스트, 전문 영상의 판독에는 오인식 가능성이 있으므로 결과를 검증해야 합니다.

[관련 개념 정리](../../topics/multimodal-vision.md)

### 2.2 Image Generation (13–26쪽)

| 작업 | API 및 기능 |
|---|---|
| 이미지 설명 생성 | Responses API + Vision 입력 |
| 새 이미지 생성 | Images API `generate` |
| 기존 이미지 편집 | Images API `edit` |

강의 예제에서는 생성된 이미지가 Base64 문자열로 반환되며, 이를 디코딩해 이미지 파일로 저장하고 Gradio에서 표시합니다.

- `gr.Image`: 이미지 한 장의 입력·출력
- `gr.Gallery`: 여러 이미지 출력
- `gr.ImageEditor`: 배경 이미지, 추가 레이어, 합성 결과 처리

강의에서 제시한 실습 모델은 `gpt-image-1-mini`입니다. 모델의 실제 지원 여부와 요금은 실행 시 확인이 필요합니다.

[관련 개념 정리](../../topics/image-generation.md)

### 2.3 Speech (27–47쪽)

| 기능 | 입력 | 출력 |
|---|---|---|
| TTS | 텍스트 | 음성 |
| STT / Transcription | 음성 | 텍스트 |
| Translation | 음성 | 번역된 텍스트 |
| STT + LLM | 음성 → 텍스트 | 번역·재작성된 문장 |

TTS는 음성의 목소리, 속도, 출력 형식 등의 옵션을 설정할 수 있습니다. STT는 녹음 파일을 입력받아 내용을 문자로 변환합니다.

강의는 STT 결과를 LLM으로 번역하면 문체나 대상 독자에 맞게 표현할 수 있다는 점을 설명합니다.

`gr.Audio`로 파일 업로드 및 마이크 입력을 받을 수 있습니다. 브라우저 마이크 권한과 공유 링크의 접근 범위를 확인해야 합니다.

강의 지정 모델: `gpt-4o-mini-tts`, `gpt-4o-mini-transcribe`. 모델별 가격 및 사용 조건은 현재 공식 문서를 별도로 확인해야 합니다.

[관련 개념 정리](../../topics/speech-audio.md)

## 6. 이미지 관련 실습

### 6.1 이미지 생성 및 편집 (19–20쪽)

- `client.images.generate()`로 원본 이미지 생성
- `result.data[0].b64_json`에서 이미지 데이터 추출
- `base64.b64decode()`로 디코딩하고 `wb` 모드로 저장
- `Image.open()`과 `display()`로 결과 확인
- `client.images.edit()`에 원본 파일과 수정 지시 전달

### 6.2 Gradio 이미지 컴포넌트 (21–23쪽)

| 컴포넌트 | 실습 내용 |
|---|---|
| `gr.Image` | Pillow의 `convert("L")`을 사용한 흑백 변환 |
| `gr.Gallery` | 45도 간격으로 회전한 이미지 8개 출력 |
| `gr.ImageEditor` | 원본 이미지와 사용자가 그린 레이어의 합성 결과 출력 |

위 예제는 코드 안내 단계이며 각각의 실행 결과는 확인되지 않았다. 흑백 변환, 회전, 레이어 합성 자체에는 생성형 AI API 호출이 필요하지 않다.

### 6.3 그림판 Artist (26쪽)

강사 답안의 API 연결, 함수 정의, Base64 파일 저장, `gr.Blocks` 및 버튼 이벤트 구조를 참고하여 구현 예제를 작성했다.

처리 흐름:

```text
ImageEditor의 composite
  → PNG 및 Base64 인코딩
  → gpt-4o-mini로 손그림 분석 및 프롬프트 작성
  → gpt-image-1-mini로 이미지 생성
  → Gradio에 결과 표시
```

수채화, 유화, 파스텔화 선택 기능과 생성 프롬프트 출력 영역을 포함했다. 실행 결과는 미확인 상태다.

## 7. 속담 그림 퀴즈 (25쪽)

**자료:** 속담 게임 실습 노트북 및 강사 답안 노트북, 사용자 실행 화면과 대화 기록.

### 구현 구조

강사가 제시한 변수와 함수 구조를 유지하는 방향으로 진행했다.

- `s = sokdam.split('\n')`: 속담 목록 분리
- `result_text`, `sco`, `tot`, `ans`: 결과, 점수, 진행 수, 현재 정답
- `draw()`: 문제 이미지 준비 및 정답 설정
- `judge(inp)`: 사용자 입력과 정답 비교
- `gr.Blocks()`: 입력 및 출력 컴포넌트 구성

추가 구현: 5문제 단위 진행, 중복 출제 방지, 연속 정답 보너스, 힌트 사용 시 감점, 문제별 결과 표시.

### 실행 및 개선 기록

| 문제 | 원인 | 대응 |
|---|---|---|
| `NameError: sokdam is not defined` | 속담 문자열 정의 셀이 실행되지 않음 | 변수 정의 셀을 먼저 실행 |
| `IncompleteInputError` | `with gr.Blocks():` 아래 본문 없이 실행 | 들여쓰기된 화면 구성 코드 추가 |
| `NameError: start_game is not defined` | 버튼에 연결할 함수가 아직 정의되지 않음 | 함수 정의 후 UI 연결. 반환값과 출력 컴포넌트 수 일치 |
| 문제 전환 약 30초 | `judge()`에서 다음 이미지 생성 API를 호출 | 게임 중에는 미리 준비한 이미지 캐시를 사용하는 방향으로 변경 |
| 이미지 잘림 및 낮은 품질 | 여러 문제를 한 이미지에 배치하고 고정 좌표로 분할 | 분할 방식 폐기. 속담별 독립 이미지 생성 및 캐시 사용 제안 |

사용자가 게임 구현 및 실행을 확인했으며, 이미지 생성 지연과 분할 이미지의 잘림은 실제 피드백 및 화면에서 확인했다. 마지막 개선안(독립 이미지 5장 사전 생성, 최대 3개 병렬 요청)의 실행 결과는 확인되지 않았다.

**학습 내용:** 정답 판정 자체와 다음 이미지 생성은 분리해야 한다. API 지연이 사용자 인터랙션을 막지 않도록 사전 생성·캐시를 활용할 수 있다. 병렬 호출은 사용량 제한과 비용을 고려해야 하며, 여러 그림을 고정 좌표로 자르는 방식은 생성 결과의 배치를 보장하지 못한다.

## 8. 음성 처리 실습 (29–47쪽)

### 8.1 TTS, STT 및 번역

| 작업 | 사용 모델 | 코드 |
|---|---|---|
| 텍스트 음성화 | `gpt-4o-mini-tts` | `client.audio.speech.create()` |
| 음성 인식 | `gpt-4o-mini-transcribe` | `client.audio.transcriptions.create()` |
| 음성 영어 번역 | `whisper-1` | `client.audio.translations.create()` |
| 전사 텍스트 번역 | `gpt-4o-mini` | `client.responses.create()` |

실습 코드에서는 TTS 결과를 MP3로 저장하고 이를 전사 및 번역 입력으로 재사용했다. 동일 파일 객체를 다시 읽을 때 `audio.seek(0)`으로 위치를 초기화하는 방법을 확인했다.

발생한 오류: `NameError: name 'client' is not defined`. OpenAI 클라이언트 초기화 셀을 먼저 실행하는 해결 방법을 안내했다. 이후 실행 성공 여부는 미확인이다.

### 8.2 통역기 APP (46쪽)

강의 과제 및 공유된 참고 화면을 통해 다음 UI 구성을 확인했다.

```text
한국어 음성 입력 → STT → 원문 표시
                     → 선택 언어로 LLM 번역 → 번역문 표시
                                         → TTS → 번역 음성 재생
```

참고 화면에서는 한국어 전사, 영어 번역문, 음성 플레이어가 표시됐다. 해당 화면이 본인의 구현 결과인지는 확인되지 않아 참고 실행 화면으로 기록한다.

### 8.3 영어 회화 퀴즈 (47쪽)

한국어 회화 문장을 무작위로 제시하고 영어 음성 답변을 받는 Gradio 구현 예제를 작성했다.

- `random.choice()`: 문제 출제
- `gr.Audio()`: 마이크 녹음 및 파일 입력
- STT: 영어 답변 전사
- LLM: 의미 전달, 문법, 표현의 자연스러움에 대한 점수 및 피드백
- JSON 결과 파싱: 점수, 피드백, 모범 답안 분리
- TTS: 모범 답안 음성 출력

전사된 텍스트만으로 실제 발음의 정확도를 평가하지 않도록 지시문에 제한을 추가했다. 실행 결과는 아직 확인되지 않았다.

## 9. 멀티모달 자율 프로젝트 (49쪽)

이미지와 음성을 결합하는 과제에 대해 오디오 그림책 제작기 구현 예제를 작성했다.

```text
손그림 또는 사진 + 음성 요청
  → STT → Vision 및 이야기 작성
  → 이미지 편집 → TTS 낭독
```

강의 지정 모델 네 종류를 사용하고, `yield`로 진행 단계별 결과를 출력하는 구조다.

실행 시 `userdata.get("openai_api")`에서 `TimeoutException`이 발생했다. Colab UI와 보안 비밀 접근 권한, 런타임 연결을 확인하도록 안내했다. API 처리 단계까지의 성공은 확인되지 않았다. 이후 사용자가 당장의 과제는 47쪽 영어 회화 퀴즈임을 확인했으므로, 그림책 제작기는 별도 자율 프로젝트 후보로 분류한다.
